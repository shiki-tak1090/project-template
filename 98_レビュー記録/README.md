# レビュー記録

設計の前提と判断の記録、設計レビューの記録を管理します（社内向け）。

- 案件全体で 1 つずつ持つもの：`設計情報.md`（設計の前提）と `設計判断ログ.md`（人が決めた判断と理由）。`/project-docs:basic-design` が作り、`/project-docs:detailed-design` が書き足す
- `基本設計/` に置くもの：未決定事項一覧（`未決定事項一覧.md`。基本設計で決められなかった事項と、後の工程で決める事項。後の工程が読み、決めたら状態を更新する）と、レビューの要旨（`レビューの要旨.md`）。発注者に確認することは `02_基本設計/仕様確定.md` にも載る
- `<機能名>/` に置くもの：確認事項一覧（詳細設計で、関係者に確認すること）
- レビューの途中経過（欠陥の台帳、ラウンドごとのレビュー記録、トレーサビリティ、反対役の確認など）は、サブフォルダの `作業中/` に置く。`/project-docs:basic-design` と `/project-docs:detailed-design` は、最後まで終わったら `作業中/` ごと消す。`作業中/` が残っていれば、レビューが途中で止まっている
