# レビュー記録

設計の前提と判断の記録、設計レビューの記録を管理します（社内向け）。

- 案件全体で 1 つずつ持つもの：`設計情報.md`（設計の前提）と `設計判断ログ.md`（人が決めた判断と理由）。`/project-docs:basic-design` が作り、`/project-docs:detailed-design` が書き足す
- 段階や機能ごとのサブフォルダ（`基本設計/`、`<機能名>/`）に置くもの：確認事項一覧（発注者以外の関係者に確認すること。発注者に確認することは、基本設計では `02_基本設計/仕様確定.md` に書く）。`基本設計/` には、基本設計の範囲の外としてほかの文書（機能の詳細設計、統合仕様、インフラ・運用など）に送った事項の一覧（`基本設計からの申し送り.md`）も置く
- レビューの途中経過（ラウンドごとのレビュー記録、トレーサビリティ、反対役の確認）は、サブフォルダの `作業中/` に置く。`/project-docs:basic-design` と `/project-docs:detailed-design` は、最後まで終わったら `作業中/` ごと消す。`作業中/` が残っていれば、レビューが途中で止まっている
