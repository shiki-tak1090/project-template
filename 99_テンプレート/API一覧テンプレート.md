**書き方のルール**

- 基本設計で作り、どの API を作るかと、どの画面が使うかを決める。要求と応答の項目、型、入力チェック、エラーの応答は、詳細設計で `04_API仕様/API設計書.md` と `openapi.yaml` に書く（API定義書）
- API ID は `API-<機能の略号>-<2 桁の連番>` の形で採番する。一度採番した ID は、API を廃止しても再利用しない
- 詳細設計で API を足すときは、この一覧にも行を足し、版を上げる。基本設計で決めた行の意味を変えるときは、基本設計への差し戻しとして扱う
- 決まっていないことは【未決定】と、何が決まっていないかを書き、未決定事項一覧（`98_レビュー記録/基本設計/未決定事項一覧.md`）に行を足す
